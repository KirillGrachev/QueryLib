Type-safe SQL,
without boilerplate.

A lightweight, zero-dependency Java library for building SQL statements,
executing them without a single try-catch, and mapping results functionally.
Example.java
public Optional<String> username(Sql sql, int id) {
    return sql.queryOne(
            Query.select("username").from("users")
                    .where("id", id),
            rs -> rs.getString("username"));
}

Fluent Builder API

Builders for SELECT, INSERT, UPDATE, DELETE and CREATE TABLE. A statement is immutable data — SQL text plus parameters — so it can be built once, logged, compared in tests and executed later against any database.

Insert insert = Query.insertInto("users")
        .value("username", "grachev_ke")
        .value("email", "emperor@example.com");

Optional<Long> id = sql.insertReturningKey(
        insert, rs -> rs.getLong(1));
// identifiers are validated at call site
Query.select("password")
        .from("invalid; DROP TABLE users");

// QueryException: INVALID_IDENTIFIER,
// no SQL is rendered at all

Enhanced Security

Table and column names are validated where the call is made: an invalid identifier throws QueryException before any SQL is rendered. Values always travel as bind parameters, and UPDATE or DELETE without WHERE demands an explicit allRows().

Safe Batching

One SQL text per batch: add() rejects a statement whose text differs from the first one, so a mismatched batch fails before the round-trip. Chunks of 500 stay under driver packet limits, and SUCCESS_NO_INFO surfaces as unknownCounts instead of a negative row count.

BatchResult result = sql.batch()
        .add(Query.insertInto("logs")
                .value("msg", "boot")
                .value("lvl", "INFO"))
        .add(Query.insertInto("logs")
                .value("msg", "ready")
                .value("lvl", "INFO"))
        .chunkSize(500)
        .execute();
List<User> users = sql.inTransaction(tx ->
        tx.selectForUpdate(
                Query.select("id", "name")
                        .from("users")
                        .where("active", true),
                rs -> new User(rs.getLong("id"),
                        rs.getString("name"))));

Centralized Execution

One Sql instance owns the DataSource and the Dialect: quoting, pagination and upsert syntax come from it, never from guesswork. Transactions, batches and a raw-connection escape hatch hang off the same object. Dialects: MYSQL, POSTGRES, H2, SQLITE, SQL_SERVER, ORACLE, ANSI, NONE.
